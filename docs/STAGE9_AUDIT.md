# Stage 9: Systematic Repository Audit

**Audit date:** 2026-10-15  
**Data used:** synthetic fixtures and synthetic identifiers only.

This audit records observed results, not inferred success. Expected behavior is
taken from the documented IITT subset, existing tests, and API contracts. No
test expectation was changed to fit an actual result.

## Scope and execution

The audit covered deterministic evaluation tests, MCP service tests, workflow
tests, dashboard authorization and review behavior, reassessment tests, local
HTTP failure paths, frontend lint/typecheck/build, Python lint/compilation, and
source paths for authentication, database access, logging, model requests, and
network proxying. A temporary in-memory SQLite database was used only for
synthetic checks where the repository's PostgreSQL fixture could not run.

## Additional audit checks

### Authentication, authorization, and queue safety

- The dashboard session endpoint fails closed without a configured trusted
  provider; a caller-supplied clinician-reference header does not establish
  identity. The focused authentication tests passed.
- The assessment review endpoint rejects unauthorized reviewers; accepted
  decisions cannot use the generic review endpoint and must use protected
  workflow approval. Override requests require both fields and are audited.
- MCP queue commits verify clinician permission, exact active approval,
  assessment version, revocation status, and idempotency. Synthetic tests passed
  for unauthorized, mismatched, stale, revoked, duplicate, and conflicting
  commit attempts.
- Browser code calls the same-origin backend proxy; no direct database client
  or write path was found in the frontend.
- **Unresolved:** dashboard queue/detail reads are unauthenticated (scenario
  17). Although records are designed to be synthetic, the free-text complaint
  field does not enforce synthetic content (scenario 18).

### Database, audit, model, and MCP failures

- Missing database configuration produces a 503 with an explicit error. A
  connection-loss/transaction-failure injection was not run.
- Audit assertions passed for validation tool calls, failed unauthorized commit
  attempts, successful queue commits, clinician rejection, and override.
  Database-backed full audit/history tests could not run without PostgreSQL.
- Malformed model output, MCP timeout, and missing protocol reference all
  returned pending-review states and did not call the commit tool.
- Real Ollama execution and the real Filesystem MCP server were not exercised in
  this run: integration flags were unset and required local services/images
  were not configured. The corresponding tests were skipped, not passed.

### Sensitive information and data leaving the local environment

- No real personal data was used. The synthetic-only schema checks patient
  references and observation source references but does not screen complaint
  free text (scenario 18).
- No outbound request to a third-party service was made during this audit.
  Source inspection found default loopback destinations for the backend and
  Ollama, but both `TRIAGE_API_URL` and `TRIAGE_OLLAMA_URL` can be configured to
  non-loopback hosts. The backend proxy forwards `Authorization` and `Cookie`
  headers to `TRIAGE_API_URL`; Ollama receives the structured evaluator result.
  Therefore no actual exfiltration was observed, but configuration can send
  request data/credentials off-host. No packet-level egress capture was run.
- The evaluator's WHO URLs are source references; the reviewed evaluator code
  does not fetch them at runtime. Clinical source documents are expected via
  the configured local reference MCP server.

## Genuine unresolved failure

The most important unresolved runtime failure is F1: the actual
`evaluate_triage_rules` call failed with `INTERNAL_ERROR` because the MCP
`EvaluateTriageInput` has no `age_months`, while the deterministic IITT
evaluator immediately requires that field. The failure is fail-closed (no
approval or queue write occurred), but it means deterministic clinical
evaluation is not reliably reachable through the MCP/workflow integration.
The next step is to align the typed contracts and explicitly provide required
age/complaint inputs before attempting another end-to-end evaluation. The
14 PostgreSQL fixture errors independently block completion of the full audit.
